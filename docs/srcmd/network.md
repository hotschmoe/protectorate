# Fleet Networking (`src/net/`)

The Zig rewrite eliminates all Go, Headscale, Tailscale/`tsnet`, and external tunnel dependencies in favor of a self-contained cryptographic fleet protocol implemented directly over Zig `std`.

## Protocol Stack

1. **Cipher Suite (`src/net/noise.zig`)**: `Noise_IK_25519_ChaChaPoly_BLAKE2s` with prologue `"protectorate-fleet-v1"`. Provides forward-secure, mutually authenticated 1-RTT sessions using static X25519 keys. Session records cap at 32 KiB plaintext + 16-byte Poly1305 tag (`max_record_wire = 32786`), with automatic expiry boundaries (1 GiB / 24h).
2. **Framing & RPC (`src/net/frame.zig`, `src/net/msg.zig`)**: Length-prefixed frames (`[u32 len][u8 kind][u64 id][payload]`) distinguishing `.request`, `.response`, `.chunk`, `.end`, and `.err`. Hub-initiated RPCs use odd IDs (`1, 3, 5, ...`); node-initiated requests use even IDs (`2, 4, 6, ...`), avoiding stream head-of-line ID collisions.
3. **Transports & Roaming (`src/net/transport.zig`, `src/node/serve.zig`, `src/hub/fleet.zig`)**: The node uses this; the hub now serves the same protocol from the loop described below.  Uniform `NoiseConn` over TCP (`std.Io.net.Stream`, default hub listener `0.0.0.0:7475`) or `--stdio` pipes (`std.Io.File`) for SSH/process bridging without opening firewall ports. `NoiseConn.dial_any_tcp` races candidate hub endpoints (LAN IPs, WireGuard IPs, DNS names such as `protectorate.hotschmoe.com`) with 150 ms Happy-Eyeballs stagger and bounded timeouts so offline LAN routes never block WireGuard roaming. Nodes send 5 s heartbeats and recycle the link if no frame arrives within 15 s; the hub's bus drops a session that receives no bytes for 20 s and suppresses the old socket's disconnect when a newly roamed socket replaces a session for the same static key.

The hub has no accept thread, per-connection threads, `PeerSession` references or per-call condition variables: see the hub fleet loop below.

## Completion IO foundation

`src/net/io.zig` defines caller-owned operation storage for accept, connect, receive, send, close, and absolute monotonic timeouts in milliseconds. A backend's `submit` either returns an error without taking ownership, or takes the operation and eventually runs its callback exactly once. Completion is deferred until the backend is driven, never invoked inside `submit` or `cancel`. The operation and any referenced buffer remain exclusively owned by the backend until the callback starts. The operation becomes idle before the callback, which may submit it again. A cancellation is a request, not a completion: the callback still runs once, with either `Cancelled` or the actual result if completion won the race. The caller keeps all storage alive until that callback, including during shutdown. A connection permits at most one pending receive and one pending send; each can complete short, and the caller advances the buffer. A close completion other than `Cancelled` relinquishes the socket, even on error; the backend must finish native cleanup. A cancelled close leaves the socket with the caller. Closing does not waive the obligation to drain the other callbacks. `now` and `random` come from the backend so simulation can control both; a real backend must supply cryptographically secure random values. Readiness backends must retry nonblocking operations when ready; completion backends can map the operation directly to native requests.

`src/net/bounded.zig` provides a fixed ring, a 50 ms tick timeout with exponential backoff and positive jitter, and a 64-slab pool with 256 KiB slabs. Bulk sends leave eight slabs for control traffic and five more for a maximum-sized incoming frame. Bulk receive admission leaves the control reserve intact and reserves the whole frame before consuming its body. Small control sends leave one slab for a receiving control frame. Slab references and the free list are owned by one loop. The static allocator wraps an existing allocator: allocations, resizes and remaps are allowed only during initialization, and freeing is allowed during initialization or deinitialization, after the static phase has ended. It tracks live allocations and asserts they are all returned at deinitialization.

The slab pool occupies 16 MiB. Compile-time and startup checks cap a fleet slot at 160 KiB, the bus object at 12 MiB excluding the pool, and a node link at 2 MiB; the bus and link bounds include their fixed hello scratch buffers.

`src/net/io_epoll.zig` is the Linux readiness backend the hub runs on. It keeps a fixed table of 512 operations and 256 watched descriptors, retries nonblocking calls after readiness, and applies TCP keepalive, `TCP_NODELAY`, and a 20-second `TCP_USER_TIMEOUT` to accepted and connected sockets. `Epoll.listen` opens the nonblocking listener. Cancellation is idempotent and deferred to polling, and a close waits for other operations on the same descriptor. An eventfd registered in the epoll set lets any thread end a poll early (`wake`); the hub uses it for commands and peer snapshots.

## Completion-driven fleet core

`fleet_bus.zig` and `node_link.zig` are generic over the completion backend. `handshake.zig` runs Noise IK over short IO completions; `channel.zig` reassembles records and frames in the slab pool and sends one bounded frame at a time. `msg.encode_fixed` writes the existing JSON shapes into caller-owned storage. A frame may use five slabs, including its length prefix. Holding an incoming frame stops further receives until its owner consumes it; chunk replies are delivered one frame at a time. Senders get `Busy` or `Full` and retry when there is capacity.

The bus has 64 reusable slots, admits at most 48 established identities, and has 16 odd-ID RPC slots per peer. The remaining slots admit handshakes and replacements. It accepts one socket at a time, closes overflow, and keeps a slot until its operations and owner-visible terminal events drain. A new authenticated session for the same node identity is installed before the old session closes; old calls terminate with `peer_replaced` and the old disconnect is suppressed. The embedder supplies a nonblocking hello hook: that hook validates the hello and peer policy, maps the key to a stable 32-byte node identity, and writes the JSON hello reply into the provided buffer. `set_allowed` copies up to 1,024 keys into bus-owned storage, updates in-progress handshakes, and closes an unauthorised session awaiting hello. The bus checks authorization again when a handshake finishes. The embedder also handles subsequent node requests, including telemetry heartbeats, and supplies their replies. RPC deadlines and the 20-second stale threshold use backend monotonic time.

`event_for` lets an embedder inspect and consume one connection's event independently of other connections, so backpressure on one peer does not prevent the owner from servicing the rest. Frame consumption remains ordered within each connection and rejects stale generations and serials.

The link races at most 16 already-resolved endpoints at 150 ms intervals. The first completed Noise handshake wins; losing operations are cancelled and their sockets drained. It sends hello, repeats the current hello as a heartbeat every five seconds, closes after 15 seconds without a complete incoming frame, and reconnects with 0.5–5 second jittered backoff. The embedder supplies and retains the hello JSON and validates the hello reply through a nonblocking hook. `set_hello` replaces the borrowed heartbeat payload on the owner loop. Incoming hub requests and outgoing response, chunk, end, and error frames use odd IDs.

The embedder constructs each bus and link at its final address and keeps the backend, slab pool, endpoint view, hooks and borrowed hello payload alive until shutdown and deinitialization. It drives the bus and links, consumes events, and handles backpressure without blocking the loop. The simulator consumes hub requests immediately and retries responses from its own bounded queue. Frame events carry a slot generation and frame serial; reads and consumption reject stale events. Shutdown cancels and drains IO before `done`; bus owners must also consume terminal and disconnect events. `deinit` clears the retained static secret. The simulator freezes its network allocator after constructing these objects. The hub drives the bus from one epoll loop (below); the node still uses the threaded transport above, and Phase 3 can connect the link to portable backends and resolved endpoints.

Dial races use a process-lifetime I/O backend and page allocator: a losing dial may remain blocked after the caller's deadline or after another dial wins. Each worker owns a race-state reference, and a winning connection transfers to the caller's I/O and allocator before return.

## Hub fleet loop (`src/hub/fleet_loop.zig`, `src/hub/fleet.zig`)

One thread owns the epoll backend, the listener, the bus and every connection. It never touches the filesystem, the journal, DNS or a lock held by another subsystem; its only locks are the fleet's own command, event and snapshot mutexes and the per-call completion mutexes, each held for a few instructions or one copy. A turn applies a published peer snapshot, pops commands, then runs up to eight passes of drive the bus, flush replies, service every slot's events and retry queued calls (it drives again after consuming so replies do not wait a tick), and then polls for at most 50 ms (2 ms while something is deferred). Commands and snapshots wake the poll through the eventfd. Every event is copied out and consumed at once, so a frame is never held across a turn; a node request waits in the bus only while the previous reply to the same peer is still unsent.

Memory is fixed at start: the loop, the epoll tables, the 16 MiB slab pool, the bus (about 10 MiB), the peer tables, the hello stash and the event ring come to about 33 MiB, all taken from a `StaticAllocator` that is frozen before the loop thread starts, so a later allocation on the loop panics in safe builds. A safe build touches every byte of it at start (resident size rises by about 42 MiB). The loop does no allocation and no filesystem work after start.

**Runtime boundary.** `FleetServer` keeps its methods. A call encodes its request on the calling thread, takes one of 64 completion slots and pushes a one-word command into a 128-entry ring; a full table or ring returns `error.Busy` at once. The caller lends its request and reply buffers and blocks on its own slot until the loop completes it, so the loop writes chunk frames and the final payload straight into the caller's buffer: chunk bytes first (one piece for log and artifact fetches, none otherwise), then the final payload (up to one frame, 1 MiB: the frame limit already bounds any reply the node can send, so no job or admission status can be stranded by a reply cap; reply buffers come from the page allocator, so only touched pages are resident). Exceeding either completes the call with `ReplyTooLarge`. A piece is one call, so a fetch of a large artifact is a run of calls and the artifact sink writes on the calling thread, never on the loop. The loop owns every deadline and completes each call exactly once: with a reply, `Timeout`, `NodeOffline` (peer gone, replaced, or the loop stopping) or `Busy` (the peer's 16 RPC slots or send queue stayed full until the deadline, or a peer already has 8 lease acquisitions waiting: waiting acquisitions are capped at 8 per peer so release, renew, cancel and status calls always find a slot).

Five non-transient failures to read a job's status fail the job in the journal. A successful status read resets the count. The runtime then issues the existing cancel RPC on a worker and records a warning if the worker or RPC fails.

**Events.** Each peer has its own 64 KiB hello stash, so a reconnect burst never fails for lack of stash space. A disconnect for a session that a newer session of the same key has replaced is dropped, so a late disconnect cannot mark a live node offline. Connected, telemetry and disconnected events go through a 32-entry ring to a consumer thread that decodes the hello and runs the runtime hooks, so commits and journal writes never run on the loop. When the ring is full, connected and disconnected events stay pending in the bus until there is room and a telemetry event is dropped (counted; hub info shows `fleet_telemetry_dropped` and `fleet_refused`, the sockets and hellos the bus turned away); the heartbeat reply never depends on the consumer. The hello reply is produced on the loop from the peer snapshot: the first frame must be a hello request (at most 64 KiB), the key must be in the snapshot, and the reply carries the node's current name. Later requests are heartbeats, hello with or without inventory, and every one gets a reply (any other request type gets an unknown-request error).

**Peer snapshot.** The runtime calls `publish_peers` at start and after a node is approved, renamed or removed. Publications are serialized, so a later publication always reflects state at least as new as an earlier one. The caller builds the allowed list under the runtime's state lock, copies it into a staging table under the snapshot mutex, sets a flag and wakes the loop, which copies it into its own table and calls `set_allowed` on the bus, which also closes established sessions whose key is no longer listed (the loop applies a pending snapshot before it handles any disconnect command; up to 1,024 peers; node ids up to 64 bytes, names truncated at 128). An unknown key is dropped before any frame is read. `RemoveNode` commits the removal, which publishes the snapshot, and then disconnects the node by id, so it cannot reconnect in between.

**Shutdown.** `shutdown` asks the loop to stop and joins it: every queued and in-flight call completes `NodeOffline`, the bus cancels handshakes and closes every socket after its operations drain, disconnect events reach the consumer, and the loop exits. `stop_and_deinit` joins the consumer after the ring drains and frees the loop. The hub entry point and the runtime both call `shutdown` before waiting for HTTP handlers or their own threads, so a call in flight does not hold up exit.

## Two-Step Node Enrollment

1. Hub exports `ptjoin1:<base64url>` (`GetEnrollment`, displayable as ASCII QR via `src/qr.zig`) containing `hub_public_key`, `hub_fingerprint` (`sha256:...`), and `addrs`.
2. Node runs `protectorate-node join <ptjoin1:...>`, generates/loads its `0o600` X25519 keypair, saves hub identity pin + addresses, and prints its public key + fingerprint.
3. Unapproved nodes fail Noise_IK responder validation (`UnknownPeer`) and are dropped before accepting any `Hello` or `Job` frame. Once owner runs `AddNode` + `ApproveNode`, node static key enters `allowed_peers` and `protectorate-node authorize` / `serve` connects and begins heartbeating.

## Bounds (`src/net/limits.zig`)

Every wire-facing quantity has a named constant; later phases of docs/design/tigerstyle-network.md reuse them.

- **Piece size** `piece_max` = 256 KiB: the most a log or artifact fetch moves per RPC. The hub never asks for more, and the node clamps the requested `limit` to it in `Runner.read_log` and `Runner.read_artifact`. The hub mirrors at most 1 MiB of a running job's log per poll, one piece per call.
- **Artifact cap** `artifact_max_bytes` = 64 MiB, the value `hub info` reports. `hub/artifact_sink.zig` refuses an artifact whose declared size exceeds it before any transfer, and refuses any piece that would take the received total past the cap or past the declared size. Pieces go to `<dest>.ptpart` while a SHA-256 runs; size and digest are checked, then the file is renamed into place. Any failure removes the temporary. Nothing holds a whole artifact in memory. A refused job reports `artifact <path> (<n> bytes) exceeds the <cap> byte artifact cap`.
- **RPC chunks** `rpc_chunks_max` = one piece: a pending call fails with `ReplyTooLarge` when its chunk frames add up to more. Non-chunk replies are one frame (at most 1 MiB) and replace each other, so they cannot accumulate.
- **Connections**: the fleet bus holds at most 64 sockets, handshakes included (`bounded.fleet_slots`); the next one is closed at once. Each HTTP server holds at most `http_conns_max` = 32; the next one gets `503 Service Unavailable` and is closed. Each gate (`ConnGate`) logs the first refusal of a burst only; a burst ends when a connection is admitted again.
- **Frame decoder**: `Decoder.feed` fails with `TooLarge` when the buffer would pass one maximum frame plus one Noise record (`decoder_buffer_max`); the decoder then stays failed.
