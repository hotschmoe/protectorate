# Data-oriented design survey

The best opportunities are avoiding work already shown by the code: a full bus-ring scan per subscriber wake, repeated history-page prefix scans, and an allocation per token segment. Most orchestration maps should stay until profiling shows otherwise. The published core view is the largest architectural duplication, but removing it safely is a larger change than replacing a collection.

The estimates below are operation counts, not measurements from this survey. The workload assumptions are 20 live sleeves, four nodes, one to three clients, a few thousand transcript entries per sleeve, and history up to a few GB.

## DO, ranked by value and cost

1. **Index the bus ring by position.** [bus.rs:345](crates/pt-hub/src/bus.rs:345) scans up to 8,192 items on every `since` wake, even when there is one new item or none. Positions are contiguous, so calculate the `VecDeque` range from the front position and `durable`, then clone only that range. Preserve the existing gap and durable-boundary checks. At a full ring, three clients currently perform up to 24,576 item comparisons for one wake each; the proposed work is proportional to returned items. **DO:** small change on the live delta path. Keep position distinct from sequence: deltas repeat a sequence number.

2. **Start history pages at the cursor.** [index.rs:1264](crates/pt-history/src/index.rs:1264) scans each segment from its first document for every `after` page. Segment decode verifies strictly ascending document IDs at [segment.rs:459](crates/pt-history/src/segment.rs:459). Use `partition_point` on each segment to skip IDs at or below `after`, then retain the existing session, scope, byte-limit, and `more` checks. **DO:** no new index or persistent state; later pages avoid repeatedly scanning the same prefix.

3. **Remove tokenizer allocations.** [token.rs:134](crates/pt-history/src/token.rs:134) collects every segment’s characters into a new `Vec`; [token.rs:43](crates/pt-history/src/token.rs:43) also keeps a heap vector of ranges. Walk previous/current/next characters with an iterator and keep up to six ranges in a fixed array. On the seventh range, use the existing whole-segment fallback. **DO:** removes one allocation per word-like segment on index construction without a new dependency. Preserve Unicode boundaries, case rules, token order and positions; the existing [tokenizer differential fuzz target](crates/pt-history/fuzz/fuzz_targets/tokenize.rs:1) is appropriate validation.

4. **Remove the job-log length cache.** [jobs.rs:196](crates/pt-hub/src/jobs.rs:196) keeps `log_bytes` beside the actual file, while append independently checks file metadata at [jobs.rs:203](crates/pt-hub/src/jobs.rs:203). Derive the length from the file and remove the duplicated field and updates. A partial write or sync error can leave the file length different from the cached value. **DO:** simpler ownership and a correctness improvement; it costs a metadata call. Preserve explicit handling of partial writes and sync failures—file length alone must not turn a failed sync into a successful durable write.

5. **Bound transcript reads.** [transcript.rs:98](crates/pt-hub/src/transcript.rs:98) materializes the entire file on open and when `after` falls outside the tail. Fold stats and retain the bounded tail as lines are read on open; for an older page, scan forward and stop after `limit` valid matching lines. Keep the existing torn/corrupt-line behavior. **DO:** avoids an entire temporary transcript and avoids parsing the suffix of an older-page request. Tail removal is a separate decision below.

6. **Intern history source references per document.** [index.rs:465](crates/pt-history/src/index.rs:465) allocates a source-key `String` in each sleeved document’s `Loc`; `add_live` repeats this at [index.rs:736](crates/pt-history/src/index.rs:736). Store the existing `u32` source symbol instead, including for pending documents, and resolve it when evicting. Avoid constructing owned outer-map keys on every document when a borrowed lookup finds the existing entry. **DO:** removes a heap allocation and duplicated path bytes per live sleeved document, with no segment-format change. Keep the existing charge calculation based on the full source key.

7. **Apply journal events as they are decoded.** [serve.rs:181](crates/pt-hub/src/serve.rs:181) builds a second complete `Vec<Event>` after journal recovery has already built owned frame payloads. Consume recovered frames, decode and apply one event at a time to a fresh state, and discard replay intents. Preserve frame-numbered errors and publish nothing if any decode fails. **DO:** removes the simultaneous decoded-event collection with a small change. Eliminating the earlier per-frame payload copies requires a broader `Recovered` API change and is **MAYBE**.

## Bitsets, layout, small lists and arenas

- **Boolean arrays — MAYBE.** The product `Vec<bool>` instances are the QR [modules and function masks](crates/pt-qr/src/lib.rs:65). Rust’s `Vec<bool>` stores bytes, not packed bits. A `Vec<u64>` bitset would reduce the two maximum-version 177×177 grids from about 62.7 KB to 7.8 KB. QR generation is a cold enrollment operation, so the speed case is weak; use the bitset if the no-boolean-array rule is intended as a firm representation rule, with QR fuzz/e2e coverage. There are also boolean vectors in QR test code.
- **Boolean fields and membership sets — SKIP.** Core sleeve flags and driver turn flags are a handful of semantically distinct fields, not large scanned arrays. String-keyed approval, tool and notice sets have dynamic identities; converting them to bitsets requires another mapping. Packing them saves little at 20 sleeves.
- **Small lists — MAYBE selectively.** The tokenizer’s six ranges are the strong fixed-array case. [Core guard windows](crates/pt-core/src/state.rs:198) have limits of two, and mail windows have a limit of eight; fixed arrays plus lengths are possible after preserving expiration and boundary behavior. They are cold and would enlarge every sleeve even when empty. Do not cap unbounded intent, approval, queue or driver-event vectors merely because they are usually short.
- **Short strings and trait objects — SKIP.** Driver protocol objects are boxed once per launch for four real implementations at [drivers/lib.rs:198](crates/pt-drivers/src/lib.rs:198); quota readers and HTTP callbacks likewise have distinct implementations. An enum or inline string type would add code without evidence that allocation or dispatch matters.
- **Structure of arrays — SKIP for sleeves and transcripts.** At 20 live sleeves, `envoy_id` scans about 20 records in the common case; the state also retains removed sleeves, so lifetime churn, not live count, is the caveat. History’s dictionary already uses parallel arrays at [segment.rs:71](crates/pt-history/src/segment.rs:71). Its metadata scan can be much larger, but the cursor fix avoids repeated prefixes without a layout migration. Consider splitting hot history metadata from `files: Box<[u32]>` only if profiling shows metadata bandwidth or per-document file-list allocations dominate.
- **Arenas and cleanup — SKIP.** JSON requests and history extraction do build temporary trees and then drop them, but a safe `Vec`-backed arena would require changing `Value` ownership and escaping lifetimes throughout the API. Existing `Vec` ownership already cleans up deterministically. Prefer bounded scratch arrays and borrowing where a specific path pays. A flat per-segment file-symbol pool is a **MAYBE** if profiling shows the `Box<[u32]>` allocation at [segment.rs:488](crates/pt-history/src/segment.rs:488) is material.

## Suggested implementation order

Each commit should keep the build green when implementation is later authorized. Use existing real-binary e2e scenarios and fuzz targets, adding scenarios or fuzz seeds where they cover the changed behavior.

1. **Bus positions:** DO 1. Validate empty results, ring wrap, lag gaps, durable boundaries, deltas and reconnect.
2. **History scanning:** DO 2 and DO 3. Validate pagination with scope and byte limits, plus tokenizer differential fuzzing for Unicode and more than six humps.
3. **Job log length:** DO 4. Exercise retry and recovery around incomplete writes and sync errors.
4. **Transcript reads:** DO 5. Exercise older pages, latest pages, corrupt lines and a torn final line.
5. **History source references:** DO 6. Validate ingest, reopen, budget eviction, source reset, commit failure and search equivalence.
6. **Journal replay:** DO 7. Validate replay equivalence, malformed frames, torn tails, corruption followed by an intact frame, and absence of replayed effects.
