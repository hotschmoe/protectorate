# Dogfood run, 2026-10-20

First run of the whole core loop with real harnesses: chat sleeves on two
dependent projects, the mailbox, a dependency notice, an escalation to the
orchestrator, two resleeves and one real approval. 15 model turns in all.

## Setup

- A scratch hub built from `feat/gap3-resleeve` on 127.0.0.1:17470 with its
  own `PROTECTORATE_HOME`, tmux socket `prot-dogfood` and
  `--msg-ack-timeout 30s`. Its `auth/<harness>` directories were symlinks to
  the real hub's, so the sleeves used the real logins without a copy. The real
  hub and the default tmux server were left alone.
- Two git repositories, `lib` (`example.com/dogfood/lib`, tag v0.1.0) and
  `app`, whose go.mod requires lib with `replace => ../lib`. The directory
  derived the edge app -> lib from that.
- Quota at the start: Claude 47% usable (5h window resets in 1h54m), Codex 99%,
  Grok credentials expired, local LLM probe HTTP 401.

| Sleeve | Harness | Mode | Role |
|--------|---------|------|------|
| df-lib | claude, then codex | chat | lib work, request target, first resleeve |
| df-app | codex, then claude | chat | app work, sends the request, second resleeve |
| df-mute | shell (`sleep 3600`) | terminal | a recipient that never acks |
| df-sup | claude | chat, `--supervised` | approval request |
| poe | pi (hotschmoe-local) | chat | orchestrator |

## What broke, and the fixes

Found by the run:

| Problem | Fix |
|---------|-----|
| Login shells in a sleeve lost the sleeve PATH (Codex could not run `protectorate`, so no mailbox) | seeded `~/.profile` restores PATH from `PROTECTORATE_SLEEVE_PATH` (1426eed) |
| `~/.local/go/bin` was not on the sleeve PATH unless the hub's own PATH had it | added to the sleeve PATH when mounted (1426eed) |
| Poe's token had no `message_*`: it could not answer an escalation | `message_*` in the default grants (f1fa5b3) |
| Codex sessions reported no model (empty in ChatStatus, "by codex openai" in the handoff) | the model from thread/start and thread/resume (b31caf3) |
| Release notices told the dependent to reply to `project:path:/tmp/.../lib` | the shortest address that resolves, `project:lib` (b327a9e) |
| Poe suggested resleeving a terminal sleeve | the role text says only chat sleeves can be resleeved |

Found while building resleeve:

- `git log` in release notices ran a repository's `gpg.program` on the host
  when the agent set `log.showSignature` and signed a commit (461ed56).
- `git status` and `git diff` on the host would run a repository's clean
  filter, so the handoff runs them in a read-only bwrap jail (8835215).
- No chat sleeve could raise a real approval (all ran autonomous), hence
  `--supervised` (c82855c).
- `make check` failed its own version test under a sub-make (951b641).

## What still hurts

- **Sibling modules do not build in a sleeve.** Each sandbox sees only its
  workspace, so app's `replace => ../lib` cannot resolve. Cross-project
  builds need a published version, a module proxy, or one workspace above
  both.
- **Grok is untested here:** its credentials had expired. Resleeve to and from
  Grok, and Grok as summarizer, are unverified.
- **The local summary fallback ran only against a fake pi in tests.** Both live
  resleeves found a subscription with spare quota.
- **The local LLM quota probe gets HTTP 401**: `--local-llm-url` has no API
  key, so pi is listed as "endpoint not confirmed reachable" although pi
  reaches it with its own models.json.
- **Default-branch notices cost turns.** Each plain commit upstream costs
  every chat-mode dependent a turn.
- **An interrupted turn leaves a weak "final message"** (the plan, not the
  result). The facts and the old transcript covered it here; a summarizer
  could still guess wrong.
- **A resleeve looks like a kill plus a spawn** to event watchers
  (`sleeve.exited`, `sleeve.spawned`, and the helper `sum-<name>` coming and
  going). Chat watchers see their stream end and must reconnect (the app
  does).
- **A message to a terminal sleeve shows `delivered`** after its reminder,
  though nothing was injected.
- **Flaky under load:** `TestDeskPolicyFlow` failed once ("node peer is
  unreachable"), and the app's chat screen test hit a layout assertion once.
  Both passed on rerun.
- **Leftover tmux servers** (`prot-chat-test-*` holding `sleeve-poe`) from a
  test run at 01:36, before this session, are still on the machine. This run
  did not start them and left them alone.
