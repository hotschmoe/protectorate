# Dogfood run, 2026-10-20

A dated record of the Go hub (bwrap sandbox, Go e2e suite); commit ids refer
to that history. The current system is described in ARCHITECTURE.md.

First run of the whole core loop with real harnesses: chat sleeves on two
dependent projects, the mailbox, a dependency notice, an escalation to the
orchestrator, two resleeves and one real approval. 15 model turns in all.

## Setup

- A scratch hub built from `feat/gap3-resleeve` on 127.0.0.1:17470 with its
  own `PROTECTORATE_HOME`, tmux socket `prot-dogfood` and
  `--msg-ack-timeout 30s`. Its `auth/<harness>` directories were symlinks to
  the real hub's, so the sleeves used the real logins without a copy. The real
  hub and the default tmux server were left alone.
- Two git repositories, `lib` (`example.com/dogfood/lib`, tag v0.1.0) and
  `app`, whose go.mod requires lib with `replace => ../lib`. The directory
  derived the edge app -> lib from that.
- Quota at the start: Claude 47% usable (5h window resets in 1h54m), Codex 99%,
  Grok credentials expired, local LLM probe HTTP 401.

| Sleeve | Harness | Mode | Role |
|--------|---------|------|------|

## What broke, and the fixes

Found by the run:

| Problem | Fix |
|---------|-----|
| Login shells in a sleeve lost the sleeve PATH (Codex could not run `protectorate`, so no mailbox) | seeded `~/.profile` restores PATH from `PROTECTORATE_SLEEVE_PATH` (1426eed) |
| `~/.local/go/bin` was not on the sleeve PATH unless the hub's own PATH had it | added to the sleeve PATH when mounted (1426eed) |
| Poe's token had no `message_*`: it could not answer an escalation | `message_*` in the default grants (f1fa5b3) |
| Codex sessions reported no model (empty in ChatStatus, "by codex openai" in the handoff) | the model from thread/start and thread/resume (b31caf3) |
| Release notices told the dependent to reply to `project:path:/tmp/.../lib` | the shortest address that resolves, `project:lib` (b327a9e) |
| Poe suggested resleeving a terminal sleeve | the role text says only chat sleeves can be resleeved |

Found while building resleeve:

- `git log` in release notices ran a repository's `gpg.program` on the host
  when the agent set `log.showSignature` and signed a commit (461ed56).
- `git status` and `git diff` on the host would run a repository's clean
  filter, so the handoff runs them in a read-only bwrap jail (8835215).
- No chat sleeve could raise a real approval (all ran autonomous), hence
  `--supervised` (c82855c).
- `make check` failed its own version test under a sub-make (951b641).

## What still hurts

- **Sibling modules do not build in a sleeve.** Each sandbox sees only its
  workspace, so app's `replace => ../lib` cannot resolve. Cross-project
  builds need a published version, a module proxy, or one workspace above
  both.
- **Grok is untested here:** its credentials had expired. Resleeve to and from
  Grok, and Grok as summarizer, are unverified.
- **The local summary fallback ran only against a fake pi in tests.** Both live
  resleeves found a subscription with spare quota.
- **The local LLM quota probe gets HTTP 401**: `--local-llm-url` has no API
  key, so pi is listed as "endpoint not confirmed reachable" although pi
  reaches it with its own models.json.
- **Default-branch notices cost turns.** Each plain commit upstream costs
  every chat-mode dependent a turn.
- **An interrupted turn leaves a weak "final message"** (the plan, not the
  result). The facts and the old transcript covered it here; a summarizer
  could still guess wrong.
- **A resleeve looks like a kill plus a spawn** to event watchers
  (`sleeve.exited`, `sleeve.spawned`, and the helper `sum-<name>` coming and
  going). Chat watchers see their stream end and must reconnect (the app
  does).
- **A message to a terminal sleeve shows `delivered`** after its reminder,
  though nothing was injected.
- **Flaky under load:** `TestDeskPolicyFlow` failed once ("node peer is
  unreachable"), and the app's chat screen test hit a layout assertion once.
  Both passed on rerun.
- **Leftover tmux servers** (`prot-chat-test-*` holding `sleeve-poe`) from a
  test run at 01:36, before this session, are still on the machine. This run
  did not start them and left them alone.

## Second run: an outside coordinator driving Codex sleeves

A Claude Code session on the hub, holding the owner token, dispatched ten
Codex sleeves (gpt-6.1-sol, `--cpu 200 --mem 5G|6G`) in two waves through the
CLI to carry out an architecture review's follow-ups: mail wake-up, sleeve
ownership, sleeve runtime, dependency diet, footprint, offline web client, the
e2e harness, then unit-test removal, a stdlib CLI and an idiomatic pass. Every
branch was merged with `--no-ff` after `make check` on the host.

What worked:

- Peer mail coordination without prompting: w-runtime announced its proto
  field numbers and w-scopes moved its field to avoid a collision; w-flutter
  mailed the Makefile change its app-only scope could not make.
- The real-binary e2e harness found a production bug on its first host run
  (tmux without a UTF-8 locale prints `-F` tab separators as `_`; fixed with
  `tmux -u`), and the slimmed suite exposed a spawn regression (below).
- An interim hub upgrade mid-run (backup, stop, one-shot YAML to JSON
  converter, binary swap by rename, restart with the same flags) kept tokens,
  nodes and sleeves identical, and Envoy resumed.

What hurt, with the wanted fix:

- **Dispatch is four steps per sleeve.** `--workspace <git url>` clones only
  the default branch, so each clone was made by hand (`--branch dev-hotschmoe`,
  a feature branch, origin reset). The brief needed a separate `chat send`.
  Wanted: `--branch/--new-branch`, cloning from a local checkout, and
  `sleeve spawn ... --brief FILE` so a sleeve never sits idle unbriefed.
- **No completion signal and no marked result.** The coordinator polled
  `sleeve ls --json`. Peer mail woke finished sleeves for an extra turn, so
  the last assistant message stopped being the report. Wanted: `chat wait
  <sleeve> --until idle` (or an owner stream of sleeve state) and a result
  event a sleeve emits once, with a completeness field: a refactor brief got a
  68-line first pass reported as done and needed concrete hotspots for pass 2.
- **Sleeves never hear that their base moved.** w-footprint redid a Makefile
  change already merged, and w2-cli could not rebase because the host checkout
  is not visible in the sandbox. Wanted: a notice when the parent branch
  advances, and a read-only view of the coordinator's branch.
- **No nested runtime.** Tests that spawn real sleeves skip inside a sleeve, so
  runtime scenarios first ran on the host at merge time, where fixture bugs
  and one never-green test surfaced. Wanted: a delegated cgroup subtree, or a
  hub-side "run this test with the runtime" job.
- **Schema merges.** The conflict points were the sleeve record (proto, Go
  struct, JSON tags) and the binary descriptor image; two semantic conflicts
  compiled only after merging. A schema-owner step (proto and state changes
  land first, others rebase) would avoid both.
- **Spawn copied 2.4 GB.** Every new sleeve copied the Flutter `bin/cache` and
  Pub caches into its home (no reflinks on ext4, no `--overlay` in bwrap 0.8):
  about 20 s per spawn. Now only Dart workspaces get the copy (150 ms spawns
  otherwise); bwrap 0.9 overlays would make it free.
- **Sleeve homes grow without bound** (one reached 43 GB of Go build cache).
  Nothing reports or trims them. Wanted: home disk in `sleeve show`, and an
  owner-confirmed cache drop on kill.
- **Notes never close.** Note 0a94 was implemented 1h40m after it was filed
  and others record completion in their body, yet all list as open. A status
  set by the worker or the merge would let a coordinator pick real work.
- **Smaller:** sleeves inherited `PROTECTORATE_TOKEN_FILE`/`PROTECTORATE_HUB`
  and broke tests that start a hub; a test hub saw production scopes (now
  isolated per state home); one brief produced a hardcoded owner path in
  product code (replaced by `hub serve --sleeve-reference-dir`); real-binary
  tests each invented their own env gate; `sleeve show` text omits read-only
  mounts and the idle timeout; the hub on this machine has no systemd unit, so
  a restart meant recovering its flags from /proc.

## Third run: eleven sleeves on the dogfood list, an audit and leaner sleeves

The same coordinator dispatched eleven Codex sleeves (gpt-6.1-sol, now at
`--effort high`; every earlier sleeve had silently run at the model's native
default, `low`, because sleeves do not inherit the owner's Codex config). Six
took the items above, two audited the day's merged code, one restored race
detection, one closed e2e coverage gaps and one made sleeves lighter
(bubblewrap 0.13.1 overlays). Proto field numbers were reserved per branch up
front; that removed the schema collisions of the second run, though every
merge still conflicted in the generated code, the descriptor image and the
test inventory.

What worked:

- The audits found real defects in code written at low effort, including a
  critical one: job-controlled Git programs ran with node-agent authority.
  Each finding was reproduced before it was fixed and has a regression
  scenario.
- `make test-race` and the nested runtime scenario both ran clean on the host
  against the fully merged tree.
- A sleeve reported itself `partial` and stopped where the brief told it to
  (launching Codex natively would have reimplemented launcher behavior outside
  the package contract) instead of claiming completion.

What hurt:

- Idle is still not done. Twice an audit sleeve ended its turn on a progress
  note, and peer mail woke finished sleeves, which answered with a plan and
  stopped. The `FINAL REPORT` marker in briefs made this detectable; the new
  `protectorate report` / `chat wait --until report` make it structural.
- A host-only scenario was never green: the dispatch test failed on the
  sleeve's own branch, because masking the base `.git/config` with
  `/dev/null` is unreadable under bwrap's `nodev` binds. Sleeves that cannot
  run runtime scenarios still ship runtime bugs; `--nested` now closes that
  gap.
- The MCP `tools/list` golden hash conflicts on every merge of two
  API-changing branches and has to be recomputed by hand. A golden file
  written by `make gen` would merge like other generated output.
- Sleeves cannot see host-scale facts. One cache design copied and hashed the
  owner's whole Go build cache at hub startup, which on this hub is 111 GB.
  Briefs for host-touching work need the relevant sizes.
- A watcher started outside the coordinator's task tracking recorded four
  completions nobody saw; `chat wait` on the hub event stream replaces that
  polling.
- The lean-sleeves branch passed everything a sleeve can run and still broke
  on the host: overlayfs creates `work/work` without permissions, which made
  the disk sampler, `hub backup` and the race-log scan fail for every overlay
  sleeve, and the hub service's PATH has no `go`, so shared Go snapshots
  would never have started. Merges of runtime-touching branches need the host
  lanes before they count as green; `--nested` sleeves can now run them.
