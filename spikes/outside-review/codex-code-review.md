# Codex code review (2026-10-19)

Three read-only `codex exec` passes over pivot-city at 9eec78e: (1) auth and privilege, (2) sandbox and credentials, (3) robustness. Findings are verbatim. Each one is verified and fixed (or rejected with a reason) in the commits that follow this one.

## Pass 1: auth and privilege

## Findings

- **High — A scoped session token can obtain owner access.** [internal/hub/sessions.go:73](../../internal/hub/sessions.go:73) passes a caller supplied command to `Sessions.Create`; [internal/session/session.go:270](../../internal/session/session.go:270) runs it as the hub’s OS user. A token granted `session_create_session` can run a command that reads the owner token from `$PROTECTORATE_HOME/token`, then call owner-only RPCs. Restrict session creation to owner credentials, or execute scoped sessions under an identity that cannot read hub state and secrets.

- **High — Node registration can disclose the hub’s node-agent token.** [internal/hub/nodes.go:378](../../internal/hub/nodes.go:378) accepts a caller supplied node address and immediately polls it; [internal/hub/nodes.go:207](../../internal/hub/nodes.go:207) sends the configured shared node token in the `Authorization` header. A scoped caller allowed to add nodes can register an address they control and receive that token. Validate destinations against trusted enrolled nodes, or use a credential bound to each node.

- **Medium — The MCP HTTP endpoint grants its bridge token’s authority to unauthenticated callers.** [internal/mcpbridge/server.go:52](../../internal/mcpbridge/server.go:52) installs no caller authentication, while [cmd/protectorate/mcp.go:49](../../cmd/protectorate/mcp.go:49) permits a non-loopback listener. Anyone who can reach such a listener can invoke every exposed tool through the bridge’s hub token; `--allow` can expose mutations. Require authentication on HTTP requests or reject non-loopback binds unless an explicit authenticated gateway is configured.

- **Medium — Long-running node credentials are exposed in process arguments.** [cmd/protectorate/node.go:213](../../cmd/protectorate/node.go:213) and [cmd/protectorate/main.go:190](../../cmd/protectorate/main.go:190) accept shared bearer tokens as command-line flags. When operators use those flags, local users able to inspect process arguments can recover the tokens for the lifetime of `node serve` or `hub serve`. Accept token files or protected environment input and remove secret-bearing flags.

## Pass 2: sandbox and credentials

1. **Critical — a symlinked state directory can expose the owner token.** [internal/sleeve/plan.go](../../internal/sleeve/plan.go:104) checks the workspace against `Config.Home` as a lexical path, while [workspace resolution](../../internal/sleeve/manager.go:651) resolves the requested path’s symlinks. If `PROTECTORATE_HOME` is a symlink to `/mnt/state`, a caller with sleeve spawn permission can request `/mnt/state` as the workspace. The check passes and the sleeve can read `/mnt/state/token`, the owner credential. **Fix:** canonicalize the state directory and all protected paths before comparing them with the resolved workspace.

2. **High — sleeve spawn can mount another sleeve’s workspace and token.** [internal/sleeve/plan.go](../../internal/sleeve/plan.go:117) rejects only selected children of the state directory; it explicitly permits `orchestrator` and `workspaces` ([test](../../internal/sleeve/plan_test.go:217)). A scoped caller can spawn a sleeve with the orchestrator directory as its workspace and read its `.protectorate-token` ([creation](../../internal/orchestrator/spawn.go:120)), or mount the workspaces directory to access other checkouts. **Fix:** authorize state owned workspaces by caller and sleeve identity; reject the orchestrator workspace for other sleeves and reject the shared workspaces parent.

3. **High — default tool mounts expose credential files.** [internal/sleeve/sleeve.go](../../internal/sleeve/sleeve.go:101) includes entire `~/.cargo` and `~/.local` directories, which [Plan binds read only](../../internal/sleeve/plan.go:193). A sleeve can therefore read a user’s `~/.cargo/credentials.toml` when present, as well as application data under `~/.local/share`; read only mounting does not protect those secrets. **Fix:** mount the executable and required runtime paths narrowly, excluding credential and application data files.

4. **High — harness binary symlinks can add credential directories to the mount list.** [internal/sleeve/plan.go](../../internal/sleeve/plan.go:41) adds every directory in a located binary’s symlink chain to `Binary.RO` without the credential check used for `AddBinaryDir`; [Plan mounts them](../../internal/sleeve/plan.go:193). For example, a harness symlink in `~/.local/bin` targeting an executable directly in `~/.codex` causes the whole `.codex` directory to be mounted. **Fix:** resolve and validate every binary target directory before adding a read only bind, and refuse directories containing credentials.

5. **High — adding a node can disclose the configured node bearer token.** [internal/hub/inventory.go](../../internal/hub/inventory.go:99) accepts an arbitrary host and port as a node address. [AddNode](../../internal/hub/nodes.go:378) immediately polls it, and [fetchHTTP](../../internal/hub/nodes.go:207) sends the hub’s configured node bearer token to that address. A caller granted `node_add_node` can register a server they control and receive that token on the first poll. **Fix:** restrict destinations to trusted node addresses before sending the shared token, or use credentials bound to each node.

## Pass 3: robustness

- **High — Hub can hang after a listener fails.** [internal/hub/hub.go:238](../../internal/hub/hub.go:238) starts session and sleeve workers with the caller’s context, then waits for them on return. If `Serve` exits because a listener fails while that context is still active, those workers keep polling and the deferred waits never finish. Give all workers a child context and cancel it before waiting.

- **High — A failed sleeve spawn can leave an untracked process running.** [internal/sleeve/manager.go:357](../../internal/sleeve/manager.go:357) returns immediately when `Sessions.Create` reports an error. But [session.Create](../../internal/session/session.go:295) can successfully create the tmux session and then fail while fetching it, for example if the request context is canceled. `Spawn` removes the sleeve record without killing that session or its scope. Run cleanup on every start error using a bounded independent context.

- **Medium — Timed-out filesystem probes can accumulate goroutines.** [internal/node/collector.go:360](../../internal/node/collector.go:360) launches a goroutine that may block in `os.Stat` on a dead network mount. The outer probe stops waiting after five seconds, but the inner goroutine remains blocked; each later collection can add another. Avoid launching repeat probes for a mount with an outstanding call, or use a probe mechanism whose work can be stopped.

- **Medium — Backlog lock expiry can permit concurrent writers.** [internal/backlog/store.go:157](../../internal/backlog/store.go:157) deletes any lock older than 30 seconds without checking whether its owner is alive. If a writer is paused or its write takes longer, a second writer can acquire the lock; the first writer’s unlock can then remove the second writer’s lock. Their final content check and rename can overlap and lose an update. Use an ownership checked lock, such as an OS file lock, instead of age alone.

- **Medium — `CapturePane` has an unbounded response and process buffer.** [internal/hub/sessions.go:106](../../internal/hub/sessions.go:106) passes the caller’s line count directly to tmux, while [session.run](../../internal/session/session.go:86) buffers all output before returning it. A large pane history or very long lines can consume substantial hub memory per concurrent request. Cap the capture size and enforce a byte limit while reading tmux output.

- **Medium — A failed sleeve save still removes the in-memory record.** [internal/sleeve/manager.go:420](../../internal/sleeve/manager.go:420) deletes the sleeve before saving and does not restore it if the save fails. With a full disk, `Kill` returns an error, subsequent lookups say the sleeve is absent, and a restart reloads the old record. Restore the entry on save failure, or persist the new state before committing it in memory.

- **Low — Audit tail loads an entire log file for a small request.** [internal/auth/audit.go:120](../../internal/auth/audit.go:120) calls `readEntries`, which appends every entry in a monthly file, even for the default `audit tail -n 50`. A large audit file can exhaust CLI memory. Keep only the last `n` entries while scanning, or read backward in bounded chunks.

## Concrete issues still present or introduced by the fixes

1. **High — A scoped caller can read the orchestrator token by claiming `poe`.** [CheckWorkspace](../../internal/sleeve/plan.go:224) treats the caller-supplied sleeve name `poe` as ownership of the orchestrator directory. [Spawn](../../internal/sleeve/manager.go:245) validates its syntax but does not reserve it; the directory contains the token written by [orchestrator/spawn.go](../../internal/orchestrator/spawn.go:122). When `poe` is not running, a caller with sleeve-spawn scope can start a sleeve named `poe` in that directory and read the token. **Fix:** reserve `poe` for an owner-only orchestrator path, and authorize state workspaces against the authenticated caller rather than a request field.

2. **High — Workspace selection still exposes host credentials.** [CheckWorkspace](../../internal/sleeve/plan.go:213) permits `~/.cargo` and `~/.local/share`; [Plan](../../internal/sleeve/plan.go:302) masks files only in tool-directory mounts, then binds the workspace at line 309. A scoped sleeve spawn with workspace `~/.cargo` can read `credentials.toml` when present. **Fix:** apply credential exclusions to workspace selection and mounts, including `.cargo` and application-data paths, or constrain scoped workspaces to approved roots.

3. **High — An ancestor of a resolved credential directory is accepted as a workspace.** [sleeve.go](../../internal/sleeve/sleeve.go:143) records a symlinked credential directory’s resolved target, but [CheckWorkspace](../../internal/sleeve/plan.go:216) rejects only workspaces *inside* that target. If `~/.codex` resolves to `/mnt/secrets/codex`, `/mnt/secrets` passes and its bind exposes `codex`. The [test](../../internal/sleeve/plan_test.go:267) explicitly expects that ancestor to pass. **Fix:** reject a workspace that contains any protected target as well, after canonicalizing it.

4. **High — Default pairing newly grants sleeve creation.** [token.go](../../cmd/protectorate/token.go:20) adds `sleeve_*` to every paired device token; [main.go](../../cmd/protectorate/main.go:389) issues it without `--host-shell`. A paired device can therefore invoke [SpawnSleeve](../../internal/hub/sleeves.go:117), choose the `poe` case above, or mount an allowed credential-bearing workspace. **Fix:** omit `sleeve_*` from default pairing and grant it explicitly only where required, after fixing workspace authorization.

5. **Medium — MCP HTTP sends its bearer token in cleartext on non-loopback binds.** [mcp.go](../../cmd/protectorate/mcp.go:50) accepts a non-loopback TCP address and serves plain HTTP at line 57. Clients must send the bridge’s hub token in `Authorization` ([server.go](../../internal/mcpbridge/server.go:59)); a network observer can capture that token and use its hub authority directly. The warning at line 55 does not prevent this. **Fix:** require loopback for plain HTTP, or serve TLS when accepting a network listener.

I found no additional concrete bypass in the method-level owner-only check or `terminal:host` enforcement. The DERP map supplies a SHA-256 certificate pin ([derp.go](../../internal/tailnet/derp.go:113)), and its `/verify` admission check uses the local Tailscale server’s fail-closed default ([derp.go](../../internal/tailnet/derp.go:221)). This was a read-only code review; I did not modify files or run tests.
